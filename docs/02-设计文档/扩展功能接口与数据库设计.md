| 模块 | 优先级 | 负责人 | 本轮范围 |

## 二、兼容性原则

1. `ApiContractFreezeTest` 中现有 v1.0 方法、路径和请求字段必须全部保留。
2. 扩展接口只允许新增，禁止修改现有请求或响应字段含义。
3. 所有业务接口继续使用统一 `ApiResponse<T>`。
4. 管理端接口统一使用 `/admin/**` 并要求 `ADMIN` 角色。
5. 组员不得修改 `frontend/src/api/http.js`、公共认证流程或既有数据库迁移。
6. Flyway 版本由组长预留：
   - `V4__create_product_favorite.sql`

   - （2026-07-29）`V6__create_product_browse_history.sql`

## 三、后台统计看板

### 3.1 汇总接口

```http
GET /admin/dashboard/summary
Authorization: Bearer <admin-token>
```

响应数据：

| 字段 | 类型 | 说明 |
|---|---|---|
| `userCount` | long | 全部账号数量 |
| `productCount` | long | 全部商品数量 |
| `onSaleProductCount` | long | 在售商品数量 |
| `orderCount` | long | 全部订单数量 |
| `pendingPaymentOrderCount` | long | 待支付订单数量 |
| `paidOrderCount` | long | 已支付、待发货订单数量 |
| `shippedOrderCount` | long | 已发货、待收货订单数量 |
| `completedOrderCount` | long | 已完成订单数量 |
| `canceledOrderCount` | long | 已取消订单数量 |
| `paidSalesAmount` | decimal | 已支付、已发货和已完成订单金额合计 |
| `generatedAt` | datetime | 统计生成时间 |

统计金额不包含待支付和已取消订单。接口为实时统计，课程项目数据量下不引入缓存。

## 四、商品收藏

### 4.1 接口

```http
GET    /favorites?current=1&size=20
GET    /favorites/{productId}/status
POST   /favorites/{productId}
DELETE /favorites/{productId}
```

规则：

1. 所有收藏接口均要求普通登录态。
2. 只能收藏存在且已上架的商品。
3. 同一用户不能生成重复收藏记录；重复收藏按幂等方式返回成功，数据库唯一索引负责并发兜底。
4. 取消未收藏商品按幂等方式返回成功，避免重复点击产生 500。
5. 收藏列表按收藏时间倒序排列，只展示当前可访问商品。

收藏状态响应：

```json
{
  "productId": 1,
  "favorited": true
}
```

收藏列表使用统一分页结构，`records` 中每条数据包含：

```json
{
  "id": 1,
  "categoryId": 2,
  "name": "示例商品",
  "subtitle": "商品副标题",
  "mainImage": "/api/uploads/example.png",
  "minPrice": 99.00,
  "totalStock": 20,
  "favoritedAt": "2026-07-28T09:30:00"
}
```

### 4.2 数据表

```text
product_favorite
- id
- user_id
- product_id
- created_at
- UNIQUE(user_id, product_id)
```

## 五、商品评价

### 5.1 接口

```http
GET  /products/{productId}/reviews?current=1&size=10
GET  /products/{productId}/reviews/summary
POST /reviews
GET  /reviews/mine?current=1&size=10
```

创建评价请求：

```json
{
  "orderItemId": 1001,
  "rating": 5,
  "content": "商品符合描述，使用体验良好。"
}
```

规则：

1. 评价人必须是订单所有者。
2. 订单必须为 `COMPLETED`。
3. 一个订单商品只能评价一次。
4. `rating` 只能为 1—5。
5. `content` 必填，去除首尾空格后长度为 1—1000。
6. 商品评价列表只返回 `PUBLISHED` 状态的数据。
7. 商品名称、SKU 信息继续从订单快照读取，避免商品修改影响历史评价。

商品公开评价列表使用统一分页结构，`records` 中只返回展示所需字段，不暴露用户、订单和订单项的内部 ID：

```json
{
  "id": 1,
  "productId": 22,
  "productName": "示例商品",
  "skuSpecs": "{\"颜色\":\"黑色\"}",
  "rating": 5,
  "content": "商品符合描述，使用体验良好。",
  "reviewerNickname": "用户昵称",
  "createdAt": "2026-07-28T09:30:00"
}
```

“我的评价”列表同样使用统一分页结构，`records` 中包含当前用户查看历史评价所需的订单快照字段：

```json
{
  "id": 1,
  "productId": 22,
  "orderId": 100,
  "orderItemId": 1001,
  "productName": "示例商品",
  "skuSpecs": "{\"颜色\":\"黑色\"}",
  "productImage": "/api/uploads/example.png",
  "rating": 5,
  "content": "商品符合描述，使用体验良好。",
  "status": "PUBLISHED",
  "createdAt": "2026-07-28T09:30:00",
  "updatedAt": "2026-07-28T09:30:00"
}
```

评分统计响应：

```json
{
  "averageRating": 4.6,
  "total": 25,
  "fiveStarCount": 18,
  "fourStarCount": 5,
  "threeStarCount": 1,
  "twoStarCount": 1,
  "oneStarCount": 0
}
```

评分统计只聚合 `PUBLISHED` 评价，平均分保留一位小数。PC 与手机商品详情共用该接口，不修改已经冻结的商品详情 DTO。

### 5.2 数据表

```text
product_review
- id
- user_id
- product_id
- order_id
- order_item_id
- rating
- content
- status
- created_at
- updated_at
- UNIQUE(order_item_id)
```

## 六、库存预警与订单导出

### 6.1 库存预警

```http
GET /admin/inventory/alerts?current=1&size=20&threshold=10&keyword=手机
```

规则：

1. 仅管理员可以访问。
2. 只统计 `ON_SALE` 商品下状态为 `ENABLED` 的 SKU。
3. 返回库存小于或等于 `threshold` 的 SKU，阈值限制为 0—100000。
4. `keyword` 可以匹配商品名称或 SKU 编码。
5. 结果按库存升序排列，缺货 SKU 优先展示。
6. 看板固定统计库存不高于 10 件的 SKU，页面可调整查询阈值。

### 6.2 订单 CSV 导出

订单管理页复用 `GET /admin/orders` 的订单号和状态筛选条件，按每页 100 条获取结果并在浏览器生成带 UTF-8 BOM 的 CSV 文件。

安全规则：

1. 联系电话和收货地址在导出前脱敏。
2. 所有字段使用 CSV 引号转义。
3. 以 `=`、`+`、`-`、`@` 开头的内容增加安全前缀，避免表格公式注入。
4. 不新增数据库表，也不修改订单状态或金额计算。

## 七、错误码预留

| 错误码 | 含义 |
|---:|---|
| `40417` | 评价对应的订单商品不存在 |
| `40928` | 商品已经收藏 |
| `40929` | 订单尚未完成，不能评价 |
| `40930` | 订单商品已经评价 |

取消收藏采用幂等设计，不为“尚未收藏”单独定义错误码。
`40928` 作为严格冲突模式的预留错误码；当前收藏接口采用幂等模式，不主动返回该错误码。
