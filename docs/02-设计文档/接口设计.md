# E-Shop 后端接口设计

> 版本：v2.0
>
> 对外 API 冻结版本：v1.0（2026-07-23）
>
> 状态：已冻结并通过自动化测试与 Docker/MySQL 冒烟测试
>
> 变更规则：见 `后端接口冻结说明-v1.0.md`

## 1. 通用约定

- 统一前缀：`/api`
- JSON 请求：`Content-Type: application/json`
- 登录鉴权：`Authorization: Bearer <JWT>`
- 分页参数：`current`（从 1 开始）、`size`
- 管理接口统一位于 `/api/admin/**`。账号管理 `/api/admin/users/**` 仅 `ADMIN` 可访问；商城运营接口允许 `ADMIN` 或 `SELLER` 访问。
- 商品分类、商品列表、商品详情和图片可匿名访问。

统一响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页数据：

```json
{
  "current": 1,
  "size": 20,
  "total": 1,
  "records": []
}
```

主要 HTTP 状态与业务码：

| HTTP | 业务码示例 | 含义 |
|---:|---:|---|
| 400 | 40001、40002、40020～40023、40030 | 参数、BCrypt 密码字节长度、上传文件、分类层级、SKU 规格、购物车数量或空购物车不正确 |
| 401 | 40101、40102 | 未登录、用户名或密码错误 |
| 403 | 40301、40302 | 无权限、账号被禁用 |
| 404 | 40410～40416 | 分类、商品、SKU、购物车项、地址、订单或用户不存在 |
| 409 | 40910～40932 | 库存不足、SKU 重复、支付超时、状态冲突、受保护管理员账号或商品/分类业务规则冲突 |
| 500 | 50000、50001 | 系统异常、文件保存失败 |

## 2. 登录与用户

| 功能 | 方法 | 路径 | 权限 |
|---|---|---|---|
| 注册 | POST | `/api/auth/register` | 匿名 |
| 登录 | POST | `/api/auth/login` | 匿名 |
| 退出 | POST | `/api/auth/logout` | 登录 |
| 当前用户 | GET | `/api/auth/me` | 登录 |
| 修改个人信息 | PUT | `/api/auth/me` | 登录 |
| 后台用户分页 | GET | `/api/admin/users` | 管理员 |
| 账号统计 | GET | `/api/admin/users/summary` | 管理员 |
| 新增买家/卖家 | POST | `/api/admin/users` | 管理员 |
| 启用/禁用用户 | PATCH | `/api/admin/users/{id}/status` | 管理员 |
| 切换买家/卖家角色 | PATCH | `/api/admin/users/{id}/role` | 管理员 |

公开注册请求新增可选 `role` 字段：

```json
{
  "username": "seller_apply",
  "password": "seller123",
  "nickname": "申请入驻商家",
  "role": "SELLER"
}
```

`role` 只允许 `USER`（买家）或 `SELLER`（商家）；旧客户端不传时默认 `USER`。买家注册后状态为 `ENABLED`，可立即登录；商家注册后状态为 `DISABLED`，需平台管理员在账号管理页审核启用后才能登录。公开注册禁止创建 `ADMIN`。

用户分页支持 `keyword`、`role=USER|SELLER|ADMIN`、`status=ENABLED|DISABLED`。平台管理员不能禁用自己、修改自己的角色或修改其他平台管理员；界面只允许新增 `USER`（买家）和 `SELLER`（卖家），禁止委派新的 `ADMIN`。角色或状态修改后，后端会在后续请求中重新读取数据库角色和状态，因此旧 JWT 也会立即按新权限生效。

创建卖家示例：

```json
{
  "username": "seller_demo",
  "password": "seller123",
  "phone": "13800000000",
  "role": "SELLER",
  "status": "ENABLED"
}
```

状态请求：

```json
{ "status": "DISABLED" }
```

## 3. 分类、商品与 SKU

### 消费者接口

| 功能 | 方法 | 路径 |
|---|---|---|
| 启用分类列表 | GET | `/api/categories` |
| 已上架商品分页 | GET | `/api/products` |
| 商品和可用 SKU 详情 | GET | `/api/products/{id}` |

商品分页支持 `current`、`size`、`categoryId`、`keyword`。

### 商家运营接口（`SELLER` 或 `ADMIN`）

| 功能 | 方法 | 路径 |
|---|---|---|
| 全部分类 | GET | `/api/admin/categories` |
| 新增分类 | POST | `/api/admin/categories` |
| 修改分类 | PUT | `/api/admin/categories/{id}` |
| 修改分类状态 | PATCH | `/api/admin/categories/{id}/status` |
| 删除空分类 | DELETE | `/api/admin/categories/{id}` |
| 全部商品分页 | GET | `/api/admin/products` |
| 商品详情 | GET | `/api/admin/products/{id}` |
| 新增商品 | POST | `/api/admin/products` |
| 修改商品 | PUT | `/api/admin/products/{id}` |
| 上架/下架商品 | PATCH | `/api/admin/products/{id}/status` |
| 删除已下架商品 | DELETE | `/api/admin/products/{id}` |
| 新增 SKU | POST | `/api/admin/products/{productId}/skus` |
| 修改 SKU | PUT | `/api/admin/skus/{id}` |
| 修改库存 | PATCH | `/api/admin/skus/{id}/stock` |
| 删除 SKU | DELETE | `/api/admin/skus/{id}` |

新增 SKU 示例：

```json
{
  "skuCode": "PHONE-BLACK-128",
  "specsJson": "{\"颜色\":\"黑色\",\"容量\":\"128GB\"}",
  "price": 2999.00,
  "stock": 100,
  "status": "ENABLED"
}
```

商品状态为 `DRAFT | ON_SALE | OFF_SALE`；上架前至少需要一个已启用 SKU。SKU 独立保存价格、库存和规格，下单时使用条件更新扣减库存，避免超卖。

修改商品、分类或 SKU 时如果省略 `status`，会保留原状态；不能禁用已上架商品的最后一个可用 SKU，也不能停用仍包含已上架商品的分类。启用分类时其全部上级分类必须处于启用状态；父分类下存在启用的子孙分类时，必须先停用子分类才能停用父分类。删除 SKU 前必须先下架商品；SKU 存在待支付、已支付或已发货订单时禁止删除，避免后续取消订单无法恢复库存。

## 4. 购物车与地址

| 功能 | 方法 | 路径 |
|---|---|---|
| 购物车列表 | GET | `/api/cart` |
| 加入购物车 | POST | `/api/cart` |
| 修改数量/选中状态 | PATCH | `/api/cart/{itemId}` |
| 删除购物车项 | DELETE | `/api/cart/{itemId}` |
| 地址列表 | GET | `/api/addresses` |
| 新增地址 | POST | `/api/addresses` |
| 修改地址 | PUT | `/api/addresses/{id}` |
| 设为默认地址 | PATCH | `/api/addresses/{id}/default` |
| 删除地址 | DELETE | `/api/addresses/{id}` |

加入购物车：

```json
{ "skuId": 1, "quantity": 2 }
```

更新购物车时 `quantity` 和 `selected` 至少传一个。系统会校验商品上架状态、SKU 状态和实时库存；多次加入同一 SKU 后的总数量也不能超过 99。

## 5. 订单与模拟支付

### 消费者接口

| 功能 | 方法 | 路径 |
|---|---|---|
| 由已选购物车项创建订单 | POST | `/api/orders` |
| 我的订单分页 | GET | `/api/orders` |
| 我的订单详情 | GET | `/api/orders/{id}` |
| 我的订单状态日志 | GET | `/api/orders/{id}/logs` |
| 模拟支付 | POST | `/api/orders/{id}/pay` |
| 取消未支付订单 | POST | `/api/orders/{id}/cancel` |
| 确认收货 | POST | `/api/orders/{id}/confirm` |

创建订单：

```json
{
  "addressId": 1,
  "remark": "工作日送货"
}
```

### 商家运营接口（`SELLER` 或 `ADMIN`）

| 功能 | 方法 | 路径 |
|---|---|---|
| 全部订单分页 | GET | `/api/admin/orders` |
| 订单详情 | GET | `/api/admin/orders/{id}` |
| 订单状态日志 | GET | `/api/admin/orders/{id}/logs` |
| 订单发货 | POST | `/api/admin/orders/{id}/ship` |
| 取消待支付订单 | POST | `/api/admin/orders/{id}/cancel` |

订单状态只允许以下流转：

```text
PENDING_PAYMENT --支付--> PAID --发货--> SHIPPED --确认收货--> COMPLETED
        |
        +--用户/管理员取消--> CANCELED（自动恢复 SKU 库存）
        |
        +--支付超时自动取消--> CANCELED（自动恢复 SKU 库存）
```

订单保存商品名称、规格、图片、单价、收货地址等快照，后续修改商品或地址不会改变历史订单。支付为课程项目使用的本地模拟支付，不接入真实资金渠道。

系统默认每分钟扫描一次创建超过 30 分钟的待支付订单。支付接口本身也校验订单创建时间，因此订单超过 30 分钟后，即使定时扫描尚未执行也不能继续支付。支付与自动取消都通过带原状态和时间条件的数据库更新竞争，只有更新成功的一方继续执行，因此不会出现已支付订单被取消或库存重复恢复。

## 6. 文件与操作日志

| 功能 | 方法 | 路径 | 权限 |
|---|---|---|---|
| 上传商品图片 | POST | `/api/admin/files/upload` | 商家或管理员 |
| 访问上传图片 | GET | `/api/uploads/{filename}` | 匿名 |
| 操作日志分页 | GET | `/api/admin/logs` | 商家或管理员 |

上传请求为 `multipart/form-data`，文件字段名为 `file`。只接受内容真实为 PNG、JPEG 或 WebP 的图片，最大 5MB；服务端生成随机文件名。返回的 `url` 可直接保存到商品 `mainImage`。

已记录的管理操作包括分类、商品、SKU、用户状态、订单发货和图片上传，日志包含操作人、模块、动作、请求地址、结果和时间。

## 7. 健康检查与联调顺序

- 健康检查：`GET /api/actuator/health`
- 本地 Docker 入口：`http://localhost:8088`
- 真实 MySQL API 冒烟测试：在项目根目录执行 `powershell -ExecutionPolicy Bypass -File scripts/api-smoke-test.ps1`
- 推荐联调顺序：
  1. 商家选择 `SELLER` 注册；平台管理员在 `/admin/users` 审核启用后，商家登录并取得 Token。
  2. 创建分类和商品。
  3. 创建 SKU 后将商品状态改为 `ON_SALE`。
  4. 普通用户注册、登录、加购、创建地址并下单。
  5. 用户模拟支付，管理员发货，用户确认收货。
