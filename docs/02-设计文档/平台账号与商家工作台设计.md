# 平台账号与商家工作台设计

> 版本：v1.0  
> 日期：2026-07-30  
> 负责人：祝意远  
> 实现目录：`eshop-release-v1.0/`

## 一、目标

在不推翻现有三端架构和后台业务代码的前提下，将原管理后台复用为商家工作台，并新增平台管理员页面，实现对买家和卖家账号的统一管理。

本项目仍按课程要求定义为三端：

1. PC 消费者端；
2. 手机 H5 消费者端；
3. Web 管理端。

Web 管理端内部按角色提供两个入口，不额外增加原生 App 或第四套前端工程：

- 平台管理：`/admin/login`，负责买家和卖家账号；
- 商家工作台：`/seller/login`，负责商城运营业务。

## 二、角色与权限

| 角色 | 中文含义 | 可访问能力 |
|------|----------|------------|
| `USER` | 买家 | PC/手机商城、购物车、地址、订单、支付、收藏、评价 |
| `SELLER` | 卖家/商家运营员 | 看板、分类、商品/SKU、库存预警、订单、评价审核、操作日志 |
| `ADMIN` | 平台管理员 | 买家/卖家账号管理；也可进入商家工作台处理运营业务 |

账号注册和管理遵循最小授权原则：

- PC、手机和商家登录页可选择买家或商家身份注册；
- 买家注册后立即启用，商家注册后保持禁用状态，等待平台管理员审核启用；
- `ADMIN` 也可直接创建买家或卖家账号；
- 不允许通过管理接口创建新的 `ADMIN`；
- `ADMIN` 账号不能被禁用或降级；
- 当前登录管理员不能修改自己的角色或禁用自己；
- 卖家不能访问 `/api/admin/users/**`；
- 角色和状态变更后，已有 JWT 在下一次请求立即按数据库最新权限生效。

## 三、页面复用方案

原后台业务页面及组件不重写，只调整为 `/seller/**` 路由：

| 商家页面 | 路径 |
|----------|------|
| 商家登录 | `/seller/login` |
| 经营看板 | `/seller` |
| 分类管理 | `/seller/categories` |
| 商品与 SKU | `/seller/products` |
| 库存预警 | `/seller/inventory` |
| 订单管理 | `/seller/orders` |
| 评价管理 | `/seller/reviews` |
| 操作日志 | `/seller/logs` |

为兼容旧书签和组员旧代码，`/admin/categories`、`/admin/products`、`/admin/inventory`、`/admin/orders`、`/admin/reviews`、`/admin/logs` 自动重定向到相应 `/seller/**` 页面。

平台管理使用独立布局：

| 平台页面 | 路径 | 功能 |
|----------|------|------|
| 平台登录 | `/admin/login` | 仅允许 `ADMIN` |
| 账号管理 | `/admin/users` | 统计、筛选、新增、角色切换、启停 |

## 四、后端接口

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| GET | `/api/admin/users` | 账号分页与角色/状态筛选 | `ADMIN` |
| GET | `/api/admin/users/summary` | 买家、卖家、启用、禁用统计 | `ADMIN` |
| POST | `/api/admin/users` | 新增买家或卖家 | `ADMIN` |
| PATCH | `/api/admin/users/{id}/role` | 在买家和卖家间切换 | `ADMIN` |
| PATCH | `/api/admin/users/{id}/status` | 启用或禁用账号 | `ADMIN` |
| `/api/admin/**`（账号管理除外） | 商城运营接口 | 原后台业务接口 | `ADMIN` 或 `SELLER` |

公开 `POST /api/auth/register` 接受可选 `role=USER|SELLER`。不传角色时兼容旧客户端并默认创建买家；传入 `ADMIN` 会被参数校验拒绝。自助注册商家默认 `DISABLED`，平台管理员审核启用后方可进入工作台。

数据库沿用 `sys_user.role` 字段，增加 `SELLER` 取值，并通过 Flyway V8 添加 `(role, status)` 联合索引。该方案不需要迁移现有账号和业务数据。

## 五、当前范围

当前课程项目采用“单店铺、多运营账号”模式：所有卖家账号共同运营同一份商品、库存和订单数据。这样能完整复用原后台，开发和测试风险较低。

如果后续升级为真正的多商户市场，需要新增店铺表，并在商品、SKU、订单项、评价和统计数据中加入 `seller_id` 或 `shop_id`，再对所有查询做商户数据隔离；这属于后续版本，不在本次范围内。

- 权限边界：卖家可运营商城但不能管理账号，买家不能进入工作台；
