3. 扩展只允许**新增**接口、表、字段；禁止修改订单状态机、金额计算、库存扣减逻辑。
4. 统一响应：`ApiResponse<T>`；分页：`PageResult<T>`。
5. 公共文件仅组长可改：
   - `frontend/src/router/index.js`
   - `frontend/src/api/http.js`
   - Flyway `V1`～`V7` 既有脚本（组员不得改编号、不得自建 V8）
6. 禁止提交：`node_modules`、`target`、`dist`、`.env`、整包覆盖。

### 2.1 `product_browse_history`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 自增 |
| user_id | BIGINT | 用户 ID |
| product_id | BIGINT | 商品 ID |
| browsed_at | DATETIME | 最近浏览时间 |
| UNIQUE(user_id, product_id) | | 同一商品只保留一条 |

### 2.2 `product_review.images_json`

- 类型：`VARCHAR(2000)`，可空。
- 语义：JSON 数组字符串，例如 `["/api/uploads/a.png","/api/uploads/b.jpg"]`。
- 最多 **3** 张；无图时存 `null` 或 `[]`。
- 旧评价无此字段值时，前端按无图展示。

H2 测试库 `schema-test.sql` 已同步上述结构。

## 三、公共能力（组长已实现）

### 3.1 登录用户上传图片

```http
POST /files/upload
Authorization: Bearer <user-or-admin-token>
Content-Type: multipart/form-data
Part name: file
```

- 规则与管理员上传一致：PNG/JPG/WEBP，最大 5MB。
- 成功响应与 `POST /admin/files/upload` 相同：`url`、`filename`、`size`。
- 未登录：401。
- 评价晒图**必须**使用本接口；不要让普通用户调 `/admin/files/upload`。

预留错误码：

| 码 | 枚举 | 含义 |
|----|------|------|
| 40033 | REVIEW_IMAGE_LIMIT | 评价图片超过 3 张 |
| 40034 | REVIEW_IMAGE_INVALID | 图片地址不合法（须为本站 `/api/uploads/` 前缀） |
| 40418 | BROWSE_HISTORY_NOT_FOUND | 浏览记录不存在（单条删除时可选） |

## 四、T1 商品浏览历史（组员 2 实现）

### 4.1 接口

```http
POST   /browse-history/{productId}
GET    /browse-history?current=1&size=20
DELETE /browse-history/{productId}
DELETE /browse-history
```

### 4.2 规则

1. 全部要求登录。
2. `POST`：商品须存在且 `ON_SALE`；已有记录则更新 `browsed_at`（幂等）。
3. `GET`：当前用户、按 `browsed_at` 倒序；建议只返回仍上架商品卡片字段（对齐收藏列表）。
4. `DELETE /{productId}`：无记录可幂等成功。
5. `DELETE /browse-history`：清空当前用户全部记录。
6. 商品详情页进入后**静默**调用 `POST`，失败不弹窗打断浏览。

### 4.3 列表项建议字段

```json
{
  "productId": 1,
  "name": "商品名",
  "mainImage": "/api/uploads/x.png",
  "minPrice": 99.00,
  "totalStock": 10,
  "browsedAt": "2026-07-29T10:00:00"
}
```

### 4.4 代码边界

- 后端包：`com.eshop.backend.browse`（新建）
- 前端：`api/browseHistory.js`、PC/手机列表页；**不改**公共 router（提交路径建议给组长接入）
- 建议路由：`/pc/history`、`/m/history`

## 五、T2 评价晒图（组员 4 实现）

### 5.1 请求扩展

`POST /reviews` 的 body **新增可选字段**（保留原有必填）：

```json
{
  "orderItemId": 1,
  "rating": 5,
  "content": "很好用",
  "imageUrls": ["/api/uploads/a.png", "/api/uploads/b.jpg"]
}
```

| 字段 | 类型 | 规则 |
|------|------|------|
| imageUrls | string[] 可选 | 0～3 个；每个须以 `/api/uploads/` 开头 |

### 5.2 响应扩展

公开评价、我的评价、后台评价列表响应**新增**：

```json
"imageUrls": ["/api/uploads/a.png"]
```

无图返回 `[]` 或省略（前端兼容两者）。

### 5.3 规则

1. 先 `POST /files/upload` 拿 URL，再提交评价。
2. 落库写入 `images_json`。
3. 不改：一单一商品一次评价、订单须 COMPLETED、评分 1～5、内容 1～1000。
4. 后台隐藏评价后，公开列表仍不展示（与现逻辑一致）。

### 5.4 代码边界

- 仅改 `review` 包、评价相关前端组件与订单评价弹窗。
- 实体增加 `imagesJson` 字段；DTO 增加 `imageUrls`。

## 六、T3 后台看板图表（组员 3 实现）

### 6.1 新增只读接口（不改 summary 旧字段）

```http
GET /admin/dashboard/sales-trend?days=7
GET /admin/dashboard/top-products?limit=10
```

均要求 `ADMIN`；未登录 401，普通用户 403。

#### sales-trend 响应示例

```json
{
  "days": 7,
  "points": [
    { "date": "2026-07-23", "orderCount": 3, "salesAmount": 199.00 }
  ]
}
```

规则：

- `days` 默认 7，范围 1～30。
- 按自然日聚合；金额只统计 `PAID` / `SHIPPED` / `COMPLETED`。
- 无订单的日期补 0。

#### top-products 响应示例

```json
{
  "limit": 10,
  "items": [
    {
      "productId": 1,
      "productName": "示例",
      "soldQuantity": 20,
      "salesAmount": 3998.00
    }
  ]
}
```

规则：

- 只统计在售商品；销量来源对齐热销（已支付/已发货/已完成订单项）。
- `limit` 默认 10，范围 1～20。
