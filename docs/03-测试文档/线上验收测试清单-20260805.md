## 一、测试规则

- 统一使用正式域名测试，不使用 `127.0.0.1:8088` 或 `localhost:8088`。
- PC 端使用电脑浏览器；手机 H5 优先使用真实手机，也可使用浏览器手机设备模式复测。
- 新建账号使用容易辨认的测试用户名，不使用个人常用密码。
- 测试商品名称统一加前缀 `[TEST]`，避免与演示商品混淆。
- 不删除已有正式商品、订单和账号；测试数据由组长在验收后统一处理。
- 管理员密码只私下提供，不得写入测试报告、聊天截图或提交到 Git。
- 每发现一个问题，必须记录页面、操作步骤、实际结果、预期结果和截图。
- 页面修改后使用 `Ctrl + F5` 强制刷新，手机端可关闭页面后重新打开。

## 八、缺陷提交格式

发现问题时复制以下模板填写：

```text
缺陷编号：BUG-日期-序号
测试人：
测试时间：
测试端：PC / 手机 H5 / 商家 / 管理员
账号角色：买家 / 商家 / 管理员
页面地址：
前置条件：
操作步骤：1.  2.  3.
实际结果：
预期结果：
出现频率：必现 / 偶现
严重程度：P0 阻塞 / P1 严重 / P2 一般 / P3 优化
关联商品 ID 或订单号：
截图或录屏：
```

严重程度说明：

- `P0`：无法登录、无法下单、数据丢失、服务不可访问。
- `P1`：核心功能错误、权限越权、金额或库存错误。
- `P2`：非核心功能异常、有可行绕过方式。
- `P3`：文字、样式、交互体验问题。
