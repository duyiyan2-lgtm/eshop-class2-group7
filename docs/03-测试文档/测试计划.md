## 五、进入与退出条件

### 5.1 进入条件

1. 当前集成分支无 Git 冲突标记。
2. 后端能够编译，前端依赖已经安装。
3. 接口冻结文档和 Flyway 版本已确定。
4. 完整回归时 Docker Desktop 可用且 `.env` 已按示例准备。

### 5.2 退出条件

1. 必做 F01～F13 全部通过。
2. 选做至少 2 项、挑战 C03 通过。
3. 后端自动化失败 0、错误 0；前端生产构建通过。
4. 致命/严重缺陷遗留为 0；一般缺陷有规避方案和负责人。
5. Docker/MySQL 最新迁移、核心 API 冒烟和三端关键路径完成最终回归。

## 八、缺陷管理

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| 致命 P0 | 无法启动、数据损坏、核心流程完全阻塞 | 立即停止集成，修复后全量回归 |
| 严重 P1 | 必做功能错误、越权、库存/金额错误 | 当日修复并增加自动化用例 |
| 一般 P2 | 局部扩展或兼容问题，有规避方式 | 进入缺陷清单，提交前处理 |
| 轻微 P3 | 文案、样式和非阻塞体验 | 集中优化，不影响核心发布 |

流程：发现 → 复现 → 定级 → 指派 → 修复 → 原用例回归 → 相邻功能回归 → 关闭。记录位于测试报告和日期化缺陷修复文档。

## 十、风险与应对

| 风险 | 应对 |
|------|------|
| Docker 网络或 Desktop 未启动 | 先完成 H2/构建；启动后补真实 MySQL，报告区分结果 |
| 组员整包交付覆盖公共文件 | 仅审查精简业务差异，由组长统一合入路由/Flyway |
| 演示数据不足或状态不合适 | 使用 V3 种子并提前准备待支付、已完成、低库存样例 |
| C03 演示等待时间过长 | 临时将超时改为 2～5 分钟，演示后恢复 30 分钟 |
| 第四成员过程材料缺失 | 只据实标记待补，不伪造姓名、日报或 Git 贡献 |
