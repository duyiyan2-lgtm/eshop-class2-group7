## 四、典型缺陷分析
### 4.1 匿名查询本人信息返回 500

- **现象**：匿名访问 `/auth/me` 时不是 401，而是空指针导致 500。
- **定位**：检查 Spring Security 匹配规则，发现 `/auth/**` 被整体放行。
- **根因**：为方便登录注册而放大了公开路径。
- **修复**：只允许 `POST /auth/register`、`POST /auth/login`，其他认证接口要求 JWT。
- **反思**：安全白名单应按 HTTP 方法和具体路径最小化配置。

### 4.2 取消订单可能重复回补库存

- **现象**：用户取消、管理员取消和 C03 扫描可能同时处理同一待支付订单。
- **定位**：按订单状态变更时序分析，发现仅在 Java 中先查状态不足以阻止并发。
- **根因**：读取与修改之间存在竞争窗口。
- **修复**：使用 `WHERE id=? AND status='PENDING_PAYMENT'` 条件更新取得处理权，只有更新成功者回补库存。
- **反思**：涉及资金、库存和状态的幂等必须落到数据库条件或唯一约束。

### 4.3 评价图片数量专用错误码不可达

- **现象**：提交 4 张评价图片时被通用 Bean Validation 提前拦截，返回 `40001`，冻结接口约定的 `40033` 永远无法返回。
- **根因**：DTO 列表上的 `@Size(max=3)` 与业务层 `ReviewImages.normalize()` 重复校验且执行顺序冲突。
- **修复**：列表数量与 URL 安全规则统一由业务层校验；新增 4 图、非法外链、图片持久化及三类响应回归。
- **结果**：真实 MySQL 冒烟已验证分别返回 `40033`、`40034`。

### 4.4 测试数据库上下文互相污染

- **现象**：增加上传目录测试属性后，全量 Maven 测试出现 H2 重复建表。
- **根因**：两个不同 Spring 测试上下文共用同一个 `mem:eshop;DB_CLOSE_DELAY=-1` 数据库名称。
- **修复**：安全测试使用独立 `eshop_auth` 数据库并隔离上传目录。
- **结果**：10 个测试类、21 项测试全部通过。

### 4.5 组员前端自动 Mock 掩盖真实接口错误

- **现象**：接口失败后页面仍显示固定商品/用户数据，看似可演示但无法验证后端。
- **定位**：合入前扫描 `mock_api`、固定 token 和请求失败降级代码。
- **根因**：交付包来自旧开发版本，Mock 没有在联调阶段移除。
- **修复**：拒绝整包合入，只提取符合冻结接口的业务差异，最终源码统一使用真实 API。
- **反思**：演示环境不能用无提示 Mock 降级；失败应真实暴露并可重试。
