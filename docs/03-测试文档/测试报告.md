本轮修复的缺陷：

1. **多字节密码触发 HTTP 500**：原校验使用字符数，而 BCrypt 限制 72 个 UTF-8 字节。现已在注册与登录前校验字节长度，超限返回 HTTP 400 / 业务码 40002。
2. **停用父分类下可启用子分类**：会在消费者端形成没有可见父节点的孤儿分类。现已要求启用分类的全部上级均启用；父分类存在启用子孙分类时禁止停用。
3. **真实 API 脚本兼容性与数据污染**：修复 Windows PowerShell 5.1 对无 BOM 中文脚本的解析问题，并增加测试数据自动清理。
4. **支付扫描间隙仍可晚付**：支付更新增加订单创建时间条件，超过支付时限后即使扫描器尚未执行也返回 40926。
5. **SKU 缺少安全删除闭环**：新增管理员删除 SKU 接口；商品必须先下架，存在未完成订单时返回 40927，防止库存回补目标被提前删除。

结论：现有后端主流程、关键边界和 Docker 真实运行环境未发现遗留阻塞性缺陷，可以继续进行三端业务页面开发与联调。
