## 二、现场演示路线（约 12 分钟）

### 2.1 环境确认（30 秒）

1. 展示 `docker compose ps`，MySQL、后端、前端状态正常。
2. 打开 `/api/actuator/health`，返回 `UP`。

### 2.2 PC 消费者完整流程（4 分钟）

1. 登录固定买家账号。
2. 商品列表按关键词搜索并切换分类。
3. 打开商品详情，选择 SKU，说明价格和库存按 SKU 管理。
4. 收藏商品，并指出浏览历史已经静默记录。
5. 加入购物车，修改数量，选择地址，提交订单。
6. 展示订单金额由服务端计算和地址/商品快照。
7. 完成模拟支付，订单进入已支付。

### 2.3 Web 管理端（3 分钟）

1. 管理员登录，展示汇总卡片、近 7 日趋势和 Top 商品。
2. 在订单页找到刚才订单并发货。
3. 简要展示商品/SKU、库存预警、评价审核、用户启停和操作日志。
4. 只抽查 1～2 个扩展，避免在菜单跳转上浪费时间。

### 2.4 手机 H5（2 分钟）

1. 打开手机端订单，查看已发货状态并确认收货。
2. 对订单项提交星级、文字和 1 张晒图。
3. 回商品详情查看公开评价，并展示个人中心的收藏/浏览历史/我的评价入口。

### 2.5 C03 挑战（2～3 分钟）

按 `docs/02-设计文档/C03演示脚本.md`：

1. 演示前临时将超时设为 2～5 分钟并重启后端。
2. 记录目标 SKU 库存，创建未支付订单，确认库存扣减。
3. 等待定时任务取消订单，确认库存恢复且状态日志有超时原因。
4. 再次等待扫描，证明库存不再增加。
5. 口述支付冲突：支付和取消都用 `status=PENDING_PAYMENT` 条件更新，只有一个成功。
6. 演示后恢复 30 分钟。

## 四、老师可能追问

### 4.1 SKU 是什么，为什么不直接放商品表？

SKU 是最小可售库存单位。同一商品的颜色、容量等规格价格和库存可能不同，因此商品保存公共信息，SKU 独立保存规格、价格、库存和状态。

### 4.2 如何防止库存变成负数？

扣减 SQL 同时要求 `stock >= quantity`，通过受影响行数判断是否成功。下单事务中任一 SKU 扣减失败就整体回滚。

### 4.3 支付和超时取消同时发生怎么办？

两者都只能把 `PENDING_PAYMENT` 改为自己的目标状态。数据库条件更新只允许一个请求成功；取消方只有取得状态转换后才回补库存。

### 4.4 为什么 JWT 能支持三个端？

三个端都通过 HTTP 请求同一后端，只需在请求头携带同一种 Bearer Token。后端不依赖某个页面或服务端 Session。

### 4.5 手机端为什么不是 App？

课程只要求 PC、Web 管理和手机端，没有要求 APK、iOS 或小程序。Vue 3 + Vant 的 H5 可用手机浏览器直接访问、无需安装，并复用后端 API，适合当前周期。

### 4.6 为什么评价图片用 JSON 而不是单独表？

每条评价最多 3 张、只随评价整体读写，JSON URL 数组实现简单且兼容旧数据；如果后续需要图片审核、排序和独立元数据，再拆分图片表更合适。

## 六、失败时的现场处理

1. 页面接口失败：先看健康检查和后端日志，不启用 Mock。
2. 路由 404：确认访问端口为 8088，并从 Nginx 入口访问。
3. C03 未及时执行：检查环境变量、后端重启和扫描间隔；用已准备的状态日志截图作补充，但不能假装现场通过。
4. 图片无法显示：检查上传 URL 是否以 `/api/uploads/` 开头及挂载目录。
5. 不在现场临时修改订单、库存、Flyway 和安全核心代码。
