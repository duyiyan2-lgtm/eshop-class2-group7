## 一、项目介绍速记

- **项目定位**：E-Shop 是一个面向买家、商家和平台管理员的多角色电子商城，覆盖商品经营、在线交易、订单履约和平台监管。
- **四个使用入口**：PC 消费者商城、手机 H5 / Android 消费者端、商家运营工作台、平台管理后台。
- **买家功能**：注册登录、分类与搜索、商品和 SKU 选择、收藏、购物车、地址、下单、模拟支付、收货与评价。
- **商家功能**：商品与 SKU 管理、库存调整、订单查看与发货、评价查看以及经营数据看板。
- **平台功能**：商家审核、买卖双方账号管理、角色与启停状态控制、评价和运营监管。
- **核心闭环**：商家发布商品 → 买家选购并下单 → 服务端计价与扣减库存 → 买家支付 → 商家发货 → 买家收货评价 → 平台监管。
- **技术结构**：Vue 3 统一前端，PC / 管理端使用 Element Plus，手机端使用 Vant；Electron 封装 PC 客户端，Capacitor 封装 Android；后端使用 Spring Boot、JWT、MySQL 与 Flyway。
- **部署方式**：MySQL、Spring Boot、Nginx 前端由 Docker Compose 编排，通过正式域名、HTTPS、CORS 与健康检查对外提供服务。

## 四、老师追问时的快速回答

### 1. SKU 是什么？

SKU 是最小可售库存单位。同一商品的颜色、容量等规格可能有不同价格和库存，所以公共商品信息放商品表，规格、价格和库存放 SKU 表。

### 2. 如何避免库存变成负数？

库存扣减 SQL 同时要求 `stock >= quantity`，用受影响行数判断是否成功；任一 SKU 扣减失败，整个下单事务回滚。

### 3. 商家数据如何隔离？

商品和订单保存 `seller_id`，商家身份由后端从 JWT 获取，不能由前端传入。商品、SKU、库存、订单、评价、看板和日志查询都按当前商家过滤；管理员保留全量权限。

### 4. 为什么同时保留手机 H5 并增加 Android 客户端？

H5 可以直接通过浏览器访问，发布和迭代速度快；Android 客户端则使用 Capacitor 封装同一套 Vue 3 + Vant 页面，能够提供 APK 交付、启动页、安全区适配等更接近原生应用的体验。两者复用业务代码和后端 API，因此增加客户端形态时没有重新开发一套商城。

### 5. 401 和 403 有什么区别？

401 表示没有登录或 Token 无效；403 表示已经登录，但当前角色没有执行该操作的权限。

### 6. 支付与超时取消同时发生怎么办？

支付和取消都要求订单当前状态必须为待支付，通过数据库条件更新竞争状态转换。只有一个请求能成功，取消方只有成功取得状态后才回补库存，因此不会同时支付和取消，也不会重复回补。

### 7. 这个项目最突出的亮点是什么？

第一，多入口共用一套数据和业务规则；第二，买家、商家、管理员形成完整交易与监管闭环；第三，服务端计价、库存条件扣减、订单状态机和商家数据隔离不是页面模拟，而是后端真实约束；第四，项目完成了自动化测试、真实数据库验证、Docker 部署和多种客户端交付。
