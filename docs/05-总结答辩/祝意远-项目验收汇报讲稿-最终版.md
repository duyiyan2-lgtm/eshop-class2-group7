## 正式讲稿

### 第 1 页：开场与项目概况（约 15 秒）

各位老师好，我是第 7 组组长祝意远。我们本次完成的项目是 E-Shop 多端电子商城。我主要负责项目总体架构、后端关键业务、组员代码集成、测试以及服务器部署。下面我将从项目定位、系统架构、核心亮点和交付成果四个方面进行介绍。

### 第 2 页：项目定位与业务范围（约 35 秒）

E-Shop 面向买家、商家和平台管理员三类用户。买家可以通过 PC、手机 H5 或 Android 客户端完成注册登录、商品搜索、SKU 规格选择、收藏、购物车、收货地址、下单、模拟支付、确认收货和评价。商家通过独立工作台管理商品、SKU、库存和订单，并完成发货和经营数据查看。平台管理员负责商家审核、买卖双方账号管理、角色及启停状态控制。三类角色共同形成了“商品发布、买家下单、商家履约、买家评价、平台监管”的完整业务闭环。

### 第 3 页：多端架构与技术方案（约 30 秒）

系统提供 PC 消费者商城、H5 与 Android 消费者端、商家工作台和平台管理后台四类入口。前端统一采用 Vue 3，PC 与管理页面使用 Element Plus，手机页面使用 Vant；PC 客户端通过 Electron 封装，Android 客户端通过 Capacitor 封装。所有入口共用 Spring Boot 后端、MySQL 数据库和 JWT 身份认证，因此商品、库存、订单和评价数据能够保持一致，同时也避免了为不同客户端重复开发业务逻辑。

### 第 4 页：核心技术亮点（约 45 秒）

项目最重要的亮点不是页面数量，而是核心交易规则由后端真实保证。下单时，商品金额由服务端根据 SKU 重新计算，不能直接相信前端传入的价格；库存通过带条件的数据库更新进行扣减，库存不足时整个事务回滚，从而避免超卖。订单会保存商品名称、规格、图片和成交价快照，所以商品后续改价或下架也不会影响历史订单。

同时，系统通过订单状态机限制支付、发货、收货等操作，防止重复支付和越级操作；商家数据按照 `seller_id` 全链路隔离，商家只能管理自己的商品、库存和订单。项目还完成了 C03 订单超时自动取消：当支付和自动取消并发发生时，只有一个状态转换能够成功，并且只有取消成功后才回补库存，避免重复回补。

### 第 5 页：测试、部署与验收证据（约 25 秒）

在质量保障方面，当前 26 项后端自动化测试全部通过，覆盖身份权限、订单状态机、库存和商家数据隔离；数据库使用 Flyway V9 管理版本，并在真实 MySQL 环境中完成接口冒烟验证。部署方面，MySQL、Spring Boot 后端和 Nginx 前端由 Docker Compose 统一编排，项目已经部署到正式 HTTPS 域名，健康检查能够正常返回 `UP`。

### 第 6 页：个人贡献与结束语（约 20 秒）

作为组长，我不仅完成了后端核心模块，还负责冻结接口和数据库结构、审查组员交付、处理路由和公共文件冲突，并把各成员模块整合成统一可运行版本。同时，我组织了多端验收、缺陷修复和部署资料整理。最终项目已经达到可运行、可验证、可部署和可交付的状态。接下来我将通过正式环境演示“买家下单、商家发货、买家收货评价”这条核心链路。我的汇报完毕，谢谢各位老师。

## 时间不足时的 2 分钟精简稿

各位老师好，我是第 7 组组长祝意远，主要负责总体架构、后端关键业务、代码集成、测试和部署。我们完成的是一个面向买家、商家和平台管理员的多角色电子商城。

买家可以在 PC、手机 H5 或 Android 客户端完成商品搜索、SKU 选择、购物车、下单、模拟支付、收货和评价；商家可以管理商品、库存和订单发货；平台管理员负责商家审核和买卖双方账号管理。三类角色形成了从商品发布到交易、履约、评价和监管的完整闭环。

项目的核心亮点是交易规则由后端真实保证：服务端重新计价，库存条件扣减防止超卖，订单快照保证历史数据不受商品修改影响；商家数据按照 `seller_id` 隔离；订单状态机防止重复或越级操作；C03 超时任务能够自动取消未支付订单，并正确处理支付与取消的并发竞争。

质量方面，26 项后端自动化测试全部通过，数据库迁移到 Flyway V9，并通过真实 MySQL 冒烟验证。项目已使用 Docker Compose 部署到正式 HTTPS 域名，健康检查返回 `UP`。最终我们交付的不只是页面，而是一套可运行、可验证、可部署的完整电子商城。谢谢老师。
