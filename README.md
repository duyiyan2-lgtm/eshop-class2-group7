## 六、Git 协作规范

1. 主分支 `main` 只存放可运行代码，禁止直接 push。
2. 功能开发使用 `feature/功能名` 分支，完成后经组长 Code Review 合并。
3. 提交信息格式：`<type>: <描述>`，type 取值：`feat` `fix` `refactor` `docs` `test` `chore`。
4. **每人每天至少一次有效提交**，提交记录将作为个人考核依据。
5. **交叉 Code Review**：每人的功能分支由相邻模块负责人审查后方可合并（审查人在合并说明中留名）。

## 八、本地运行与验证

### 1. 准备环境变量

在 PowerShell 中进入仓库根目录，然后进入阶段成果文件夹并准备环境变量：

```powershell
Set-Location '.\eshop-release-v1.0'
Copy-Item .env.example .env
```

`.env.example` 中的账号和密钥仅用于本地开发，正式部署前必须修改。

### 2. 启动完整项目

```powershell
docker compose up -d --build
docker compose ps
```

容器健康后可访问：

- PC 消费者端：<http://localhost:8088/pc/products>
- 平台管理入口（管理买家/卖家）：<http://localhost:8088/admin/login>
- 商家工作台（复用原后台业务能力）：<http://localhost:8088/seller/login>
- 手机 H5 端：<http://localhost:8088/m>
- 后端健康检查：<http://localhost:8088/api/actuator/health>

本地管理员账号配置在 `.env` 的 `BOOTSTRAP_ADMIN_*` 变量中。

### 3. 运行后端接口冒烟测试

```powershell
.\scripts\api-smoke-test.ps1
```

测试脚本会创建独立测试数据，完成买家/商家区分注册、商家审核启用、账号权限、商品/SKU、购物车、下单、支付、发货、确认收货、评价审核、热销排行和取消订单等流程，并在结束后自动清理测试数据。

### 4. 停止项目

```powershell
docker compose down
```
