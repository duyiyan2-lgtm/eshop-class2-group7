# 组长模块说明

## 一、已提供的公共能力

| 能力 | 位置 | 组员使用方式 |
|---|---|---|
| 统一响应 | `backend/.../common/ApiResponse` | 所有 Controller 返回 `ApiResponse.success(data)`；业务失败抛出 `BusinessException`。 |
| 全局异常 | `backend/.../common/GlobalExceptionHandler` | 不要在 Controller 中重复 `try/catch` 后手工拼接错误响应。 |
| JWT 鉴权 | `backend/.../security` | 前端请求会自动带 `Authorization: Bearer <token>`；普通业务接口默认需登录。 |
| 角色权限 | `SecurityConfig` | 后台接口必须以 `/admin/**` 开头；该前缀自动限制为 `ADMIN` 角色。 |
| 用户身份 | `LoginUser` | Controller 可使用 `@AuthenticationPrincipal LoginUser user` 获取当前用户 ID 和用户名。 |
| 三端入口 | 前端 `/pc`、`/m`、`/admin` | B、C、D 分别在自己的终端目录添加页面和业务路由。 |
| 后台操作日志 | `admin/operationlog` | 管理员修改商品、订单、用户时，在对应方法加 `@OperationLogAction`。 |

## 二、认证接口合同

| 方法 | 地址 | 权限 | 用途 |
|---|---|---|---|
| POST | `/api/auth/register` | 公开 | 注册普通消费者账号。 |
| POST | `/api/auth/login` | 公开 | 登录并取得 JWT。 |
| POST | `/api/auth/logout` | 登录 | 前端清除 JWT；当前为无状态实现。 |
| GET | `/api/auth/me` | 登录 | 获取当前登录用户。 |
| GET | `/api/admin/logs` | 管理员 | 分页查看后台操作日志。 |

注册请求：

```json
{
  "username": "zhangsan",
  "password": "123456",
  "nickname": "张三"
}
```

登录成功响应中的 `data`：

```json
{
  "userId": 1,
  "username": "admin",
  "nickname": "系统管理员",
  "role": "ADMIN",
  "token": "eyJ..."
}
```

## 三、后台操作日志接入示例

商品、订单、用户负责人只需在“成功执行写操作”的 Service 方法上添加注解：

```java
@OperationLogAction(module = "商品", action = "商品上架")
public void publishProduct(Long productId) {
    // 商品模块自己的业务代码
}
```

日志模块只记录操作人、模块、动作、地址、成功/失败和异常类型；不记录密码、JWT 或完整请求参数。

## 四、共享表边界

`sys_user` 的账号、密码、角色与状态由组长模块定义。D 成员可以实现后台启用/禁用用户和个人资料更新，但不能私自修改建表脚本或认证字段的语义；若需新增字段，先更新数据库设计和接口设计文档。

## 五、本地启动

1. 将 `.env.example` 复制为 `.env`，开发时可保留示例管理员，提交或部署前必须更换所有密码和 JWT 密钥。
2. 推荐在项目根目录执行 `docker compose up -d --build`，MySQL、后端和前端会按健康检查顺序启动。
3. 若单独启动后端，必须先在终端设置 `.env` 中的 `JWT_SECRET`、数据库及管理员初始化环境变量，再进入 `backend` 执行 `mvn spring-boot:run`。
4. 若单独启动前端，进入 `frontend`，执行 `npm ci` 与 `npm run dev`。
5. 浏览器访问：PC `/pc`，手机 H5 `/m`，后台 `/admin`；服务健康状态为 `/api/actuator/health`。

当 `BOOTSTRAP_ADMIN_ENABLED=true` 时，首次启动会按照 `.env` 中的配置创建管理员。创建完成后应改为 `false`；生产环境禁止使用示例密码。
