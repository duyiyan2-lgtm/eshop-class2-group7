# E-Shop 服务器更新部署指南

适用环境：阿里云 Linux、宝塔反向代理、Docker Compose，正式域名 `https://eshop.zhuyiyuan9.top`。

## 一、部署前提

1. 本地优化代码已经提交并推送到个人 Gitee 仓库的 `master` 分支。
2. 服务器项目目录为 `/www/wwwroot/eshop/eshop-class2-group7`。
3. 正式环境 `.env` 只保留在服务器，不提交到 Git，也不要用 `.env.example` 覆盖。
4. 宝塔反向代理目标保持为 `http://127.0.0.1:8088`。

## 二、备份配置与数据库

```bash
cd /www/wwwroot/eshop/eshop-class2-group7/eshop-release-v1.0

cp -a .env ".env.backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p backups
docker compose exec -T mysql sh -c \
  'exec mysqldump --no-tablespaces --single-transaction --quick --set-gtid-purged=OFF -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' \
  > "backups/eshop-$(date +%Y%m%d-%H%M%S).sql"
```

备份文件只留在服务器，不要提交到仓库。

`--no-tablespaces` 用于避免普通应用账号因缺少 MySQL `PROCESS` 权限而备份失败，不需要为应用账号额外授予高权限。

## 三、同步最新 master

```bash
cd /www/wwwroot/eshop/eshop-class2-group7
git status --short
git fetch origin
git switch master
git pull --ff-only origin master
```

如果 `git status --short` 显示服务器上有人直接修改过受 Git 管理的源码，应先单独备份或 `git stash` 这些源码，再更新；不要删除 `.env`、上传目录和数据库卷。

## 四、检查正式配置

只检查配置项是否存在，不要在截图、群聊或报告中输出真实密码和密钥：

```bash
cd /www/wwwroot/eshop/eshop-class2-group7/eshop-release-v1.0

grep -E '^(CORS_ALLOWED_ORIGIN_PATTERNS|BOOTSTRAP_ADMIN_ENABLED)=' .env
```

正式环境应包含：

```dotenv
CORS_ALLOWED_ORIGIN_PATTERNS=https://eshop.zhuyiyuan9.top
BOOTSTRAP_ADMIN_ENABLED=false
```

`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`JWT_SECRET` 必须使用服务器自己的强随机值。已有数据库不能只修改 `.env` 中的 MySQL 密码，否则应用会与数据库失去连接；需要轮换时必须同时修改 MySQL 用户密码。

## 五、重新构建并启动

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

正常结果应为：

- `mysql`：`healthy`
- `backend`：`healthy`
- `frontend`：`Up`

如果启动失败，先查看：

```bash
docker compose logs --tail=120 backend
docker compose logs --tail=80 frontend
```

## 六、上线验证

```bash
curl -fsS http://127.0.0.1:8088/api/actuator/health
curl -I https://eshop.zhuyiyuan9.top/
curl -I https://eshop.zhuyiyuan9.top/m/products
```

健康接口应返回 `{"status":"UP"}`。随后用电脑和手机浏览器完成以下人工验收：

1. 统一入口可以切换 PC、手机、商家和平台管理端。
2. 手机端首页、商品详情、搜索与分类无横向滚动，底部导航和购买栏不遮挡内容。
3. 买家可以登录、加入购物车、选择地址、下单、模拟支付和查看订单。
4. 商家可以查看自己的订单并发货，不能操作其他商家的数据。
5. 平台管理员可以管理买家和卖家账号。

## 七、日常更新注意事项

- 日常发布只执行“备份 → `git pull --ff-only` → `docker compose up -d --build` → 验证”。
- 不执行 `docker compose down -v`，该命令会删除数据库卷。
- 不把 3306 和后端 8080 端口开放到公网；公网只开放 80/443，8088 可仅供本机反向代理使用。
- `.env`、数据库备份、上传文件目录需要定期备份。
