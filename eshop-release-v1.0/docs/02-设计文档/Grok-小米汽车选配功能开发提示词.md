# Grok 开发提示词：小米汽车商品分类与车辆选配功能

## 1. 使用方法

1. 按“提示词 0 → 8”的顺序逐段发送给 Grok，不要一次性全部发送。
2. 每个阶段都要求 Grok 先列出改动文件、风险和验收结果，再进入下一阶段。
3. 项目目录固定为：`C:\Users\duyiyan\Desktop\eshop-class2-group7\eshop-release-v1.0`。
4. 当前仓库存在其他未提交改动，Grok 必须保留并兼容，禁止执行 `git reset --hard`、`git checkout -- .`、批量覆盖或删除用户文件。
5. 页面只参考小米汽车选配器的交互结构和流畅体验，禁止复制对方源码、文案、商标图形、3D 模型或受版权保护的图片。车辆素材必须使用得到授权的素材、自制示意图或明确标注为课程演示的占位图，禁止直接盗链官网资源。
6. 本功能定位为“课程项目中的品牌汽车商品演示”，页面显著位置增加“非小米汽车官方页面，仅用于课程项目演示”的说明。

## 2. 已确认的参考特征

- 官方车型入口当前包含新一代小米 SU7、小米 YU7 和小米 SU7 Ultra。
- 参考选配流程：选择车型/版本 → 外观颜色 → 轮毂 → 内饰 → 其他选装 → 实时总价 → 配置清单/重置/保存。
- 页面体验重点：大幅车辆展示区、分组选择卡、选中反馈、实时价格、固定操作区、配置预览、平滑切换和按需加载。
- 本项目现有数据结构：`category → product → product_sku`，购物车按 `sku_id` 保存，订单项已有 `sku_specs` 快照；因此车辆“版本”可以作为 SKU，但颜色、轮毂、内饰等选装必须进行后端校验并保存快照，不能只存在前端内存中。

参考资料：

- 小米汽车官网：https://www.xiaomiev.com/
- 用户提供的选配页：https://www.xiaomiev.com/configurator/select?goodsId=900010301&itemId=500023067&ssuId=600046405&type=3d
- 新一代 SU7：https://www.xiaomiev.com/su7
- SU7 Ultra：https://www.xiaomiev.com/ultra

## 提示词 3：实现车辆选配后端 API

```text
请实现车辆选配后端 API，并与现有 /api 前缀、ApiResponse、鉴权和异常处理保持一致。

建议接口：
- GET /vehicles/{productId}/configurator：返回车型、可售 SKU、选项分组、可选值、兼容关系、默认配置和基础价。
- POST /vehicles/{productId}/configurator/quote：请求 skuId + optionValueIds，返回服务端校验后的配置摘要、基础价、选装价、总价、configurationHash 和可购买状态。
- POST /cart/items：兼容车辆配置参数，普通商品调用保持不变。
- 订单创建接口读取购物车保存的已验证配置，不接受客户端直接指定最终价格。

要求：
1. API 对不存在、下架、跨商品、重复分组、禁用选项、SKU 不兼容和库存不足给出明确中文业务错误。
2. optionValueIds 在计算哈希前排序，保证同一配置顺序不同仍为同一配置。
3. 报价结果不能长期信任；加入购物车和下单都必须重新校验价格及选项状态。
4. 车辆选配查询是匿名可读，购物车和订单必须登录；卖家只能维护自己商品的选配数据，管理员按项目权限执行。
5. DTO 不暴露数据库内部字段；金额序列化保持两位小数。
6. 为价格计算、组合校验、购物车不同配置不合并、订单快照、越权访问编写单元/集成测试。
7. 普通商品的商品详情、加购和下单回归测试必须保持通过。

请先展示 API 契约，再实现代码和测试，最后汇总测试数量与结果。
```

## 3. 最终验收红线

- 不是只做一个外观页面：必须能报价、加购、下单并保存车辆配置快照。
- 价格必须由后端计算，不能相信浏览器提交的总价。
- 普通商品流程必须继续可用。
- 不盗链官网图片、不复制官网源码、不假冒小米官方商城。
- 迁移不能依赖固定 ID，不能破坏服务器已有数据。
- 所有测试结果必须真实，未执行的项目必须标记“未验证”。
