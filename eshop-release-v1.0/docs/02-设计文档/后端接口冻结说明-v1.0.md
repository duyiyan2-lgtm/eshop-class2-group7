# E-Shop 后端接口冻结说明 v1.0

> 冻结日期：2026-07-23
> 冻结状态：已冻结，可供 PC 消费者端、手机 H5 端和管理端并行开发
> 统一入口：`http://<部署地址>/api`

## 1. 冻结结论

当前后端包含 10 个控制器、48 个业务接口，已经通过 13 项 Spring Boot 自动化测试和 41 项 Docker/MySQL 真实接口检查。自本版本起，三端前端统一以 `docs/02-设计文档/接口设计.md` 为接口依据。

冻结范围包括：

- HTTP 方法和 URL 路径；
- 请求参数名、JSON 字段名和字段类型；
- 统一响应结构与分页结构；
- JWT 请求头格式；
- 商品、SKU、订单等业务状态值；
- 主要 HTTP 状态与业务错误码；
- MySQL Flyway V1～V3 数据结构。

`/api` 由 Nginx 对外提供，前端只能请求 `/api/**`，不能直接访问后端容器端口。

## 3. 前端必须遵守的公共契约

### 3.1 认证

登录后保存返回的 JWT，访问登录接口以外的受保护接口时发送：

```http
Authorization: Bearer <token>
```

- HTTP 401：Token 缺失、无效、过期或账号已被禁用，清除本地登录状态并跳转登录页。
- HTTP 403：账号已登录但角色不允许访问，不要清除 Token。

### 3.2 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- HTTP 2xx 且 `code=0` 表示成功。
- 非 2xx 时优先显示响应中的 `message`。
- 删除、退出等无返回数据的接口，成功时 `data=null`。

### 3.3 分页

```json
{
  "current": 1,
  "size": 20,
  "total": 100,
  "records": []
}
```

前端统一从第 1 页开始；消费者端单页最多 50 条，管理端订单最多 100 条。

### 3.4 金额与时间

- 金额使用十进制数展示，页面统一保留两位小数，禁止使用浮点运算重新计算订单金额。
- 时间字段为服务器本地时间的 ISO-8601 格式，例如 `2026-07-23T20:30:00`。
- 商品与 SKU 库存以接口最新返回值为准。

## 4. 冻结请求字段

| 请求 | 固定字段 |
|---|---|
| 注册 | `username`、`password`、`nickname` |
| 登录 | `username`、`password` |
| 修改个人信息 | `nickname`、`phone` |
| 分类 | `parentId`、`name`、`sortOrder`、`status` |
| 商品 | `categoryId`、`name`、`subtitle`、`mainImage`、`detail`、`status` |
| SKU | `skuCode`、`specsJson`、`price`、`stock`、`status` |
| 状态修改 | `status` |
| 库存修改 | `stock` |
| 加入购物车 | `skuId`、`quantity` |
| 修改购物车 | `quantity`、`selected` |
| 地址 | `receiverName`、`phone`、`province`、`city`、`district`、`detail`、`isDefault` |
| 创建订单 | `addressId`、`remark` |

前端不要发送表中不存在的业务字段，也不要自行改变字段大小写。

## 5. 固定状态值

```text
用户角色：USER | ADMIN
用户状态：ENABLED | DISABLED
分类状态：ENABLED | DISABLED
商品状态：DRAFT | ON_SALE | OFF_SALE
SKU 状态：ENABLED | DISABLED
订单状态：PENDING_PAYMENT | PAID | SHIPPED | COMPLETED | CANCELED
支付记录状态：SUCCESS
```

三端必须直接使用这些英文值作为接口值，中文只用于页面显示。

## 6. 允许与禁止的变更

### 无需改变接口版本

- 修复内部 Bug，但不改变正常请求的字段、状态和含义；
- SQL、缓存、日志和性能优化；
- 增加自动化测试；
- 修改页面文案；
- 增加不影响客户端的内部配置。

### 兼容变更：升级为 v1.x

- 新增独立接口；
- 响应中增加可选字段；
- 新增业务错误码；
- 新增可选查询参数。

兼容变更也必须先由组长确认，并同步接口文档与契约测试。

### 破坏性变更：必须升级为 v2

- 删除或重命名接口；
- 修改 HTTP 方法或路径；
- 删除、重命名请求/响应字段；
- 修改字段类型或必填规则；
- 修改已有状态值或错误码含义；
- 修改订单状态流转；
- 修改金额单位。

未经组长确认，任何成员不得进行破坏性变更。

## 7. 变更流程

1. 模块负责人提出接口变更原因和受影响的三端页面。
2. 组长确认是否确有必要，并确定版本号。
3. 先修改 `接口设计.md` 和本冻结说明。
4. 修改后端代码及自动化测试。
5. 修改 `ApiContractFreezeTest` 中的冻结契约。
6. 后端完整测试通过后通知三端负责人。
7. 三端负责人完成兼容修改并在合并记录中确认。

禁止先改代码、后补文档。

## 8. 自动检查

冻结契约测试位于：

```text
backend/src/test/java/com/eshop/backend/ApiContractFreezeTest.java
```

该测试会检查：

- 48 个控制器方法及路径是否发生变化；
- 主要请求 DTO 的 JSON 字段是否发生变化。

运行方式：

```powershell
cd backend
mvn test
```

如果契约测试失败，先确认是否有人误改接口；不要直接修改期望值绕过测试。
